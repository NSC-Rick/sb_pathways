## Solution Architecture

### New Navigation Model

**Before V3.3 (Multipage):**
```
app.py (home page)
pages/
  ├── idea_exploration.py (auto-detected by Streamlit)
  ├── loan_readiness.py (auto-detected by Streamlit)
  ├── recovery_stabilization.py (auto-detected by Streamlit)
  └── business_transition.py (auto-detected by Streamlit)

Navigation: st.switch_page("pages/idea_exploration.py")
Result: Streamlit generates automatic navigation menu
```

**After V3.3 (Single-Page with Session State):**
```
app.py (single entry point with routing)
views/
  ├── home.py (render_home() function)
  ├── idea_exploration.py (render_idea_exploration() function)
  ├── loan_readiness.py (render_loan_readiness() function)
  ├── recovery_stabilization.py (render_recovery_stabilization() function)
  └── business_transition.py (render_business_transition() function)

Navigation: st.session_state.current_page = "idea_exploration"; st.rerun()
Result: No automatic navigation, complete custom control
```

### Routing Implementation

**Session State Management:**
```python
# Initialize session state for navigation
if "current_page" not in st.session_state:
    st.session_state.current_page = "home"

# Sidebar navigation
if st.button("🏠 Home", use_container_width=True, key="nav_home"):
    st.session_state.current_page = "home"
    st.rerun()

# Route to appropriate view
if st.session_state.current_page == "home":
    render_home()
elif st.session_state.current_page == "idea_exploration":
    render_idea_exploration()
# ... etc
```

**Benefits:**
- No automatic Streamlit navigation
- Full control over routing logic
- Clean URL structure
- No file-based page detection
- Eliminates multipage architecture entirely

## Implementation Details

### Session State Routing Pattern

**Initialization:**
```python
# In app.py, before sidebar
if "current_page" not in st.session_state:
    st.session_state.current_page = "home"
```

**Navigation Buttons:**
```python
# Sidebar navigation
if st.button("💡 Idea Exploration", use_container_width=True, key="nav_idea_exploration"):
    st.session_state.current_page = "idea_exploration"
    st.rerun()
```

**Routing Logic:**
```python
# Main content routing
if st.session_state.current_page == "home":
    render_home()
elif st.session_state.current_page == "idea_exploration":
    render_idea_exploration()
elif st.session_state.current_page == "loan_readiness":
    render_loan_readiness()
elif st.session_state.current_page == "recovery_stabilization":
    render_recovery_stabilization()
elif st.session_state.current_page == "business_transition":
    render_business_transition()
else:
    # Fallback to home if unknown page
    st.session_state.current_page = "home"
    render_home()
```

### View Function Pattern

**Standard structure for all pathway views:**
```python
"""
[Pathway Name] pathway view
Renders the [Pathway Name] pathway content
"""

import streamlit as st
from pathway_config import PATHWAYS
from content.video_links import VIDEO_LINKS
# ... other imports

def render_[pathway_name]():
    """Render the [Pathway Name] pathway"""
    
    # Get pathway configuration
    pathway = PATHWAYS["pathway_key"]
    
    # Render pathway header
    render_pathway_header(...)
    
    # ... pathway content
    
    # Navigation
    if st.button("← Back to Home", use_container_width=True):
        st.session_state.current_page = "home"
        st.rerun()
    
    # Footer
    render_footer()
```

## Navigation Flow

### User Journey

**1. Application Start:**
- User visits application
- `app.py` loads
- Session state initialized to `"home"`
- `render_home()` displays home page

**2. Pathway Selection:**
- User clicks "Start Idea Exploration" button
- Button handler sets `st.session_state.current_page = "idea_exploration"`
- `st.rerun()` triggers app refresh
- Routing logic calls `render_idea_exploration()`
- Idea Exploration pathway displays

**3. Return to Home:**
- User clicks "← Back to Home" button
- Button handler sets `st.session_state.current_page = "home"`
- `st.rerun()` triggers app refresh
- Routing logic calls `render_home()`
- Home page displays

**4. Sidebar Navigation:**
- User clicks sidebar pathway button
- Button handler updates session state
- App reruns with new view
- Seamless navigation experience

### State Persistence

**Session state maintains:**
- Current page location
- User's navigation history (via browser)
- Any other session-specific data

**Benefits:**
- Fast navigation (no page reloads)
- Maintains Streamlit session
- Clean user experience
- No URL changes (single-page app)

## Migration Guide

### For Future Pathway Addition

**Old approach (multipage):**
1. Create `pages/new_pathway.py`
2. Add page configuration
3. Streamlit auto-detects and adds to navigation

**New approach (session state):**
1. Create `views/new_pathway.py` with `render_new_pathway()` function
2. Add pathway to `pathway_config.py`
3. Import render function in `app.py`
4. Add routing case in `app.py`
5. Add sidebar button (automatic via config loop)

**Example:**
```python
# In views/new_pathway.py
def render_new_pathway():
    """Render the New Pathway"""
    pathway = PATHWAYS["new_pathway"]
    # ... pathway content

# In app.py
from views.new_pathway import render_new_pathway

# Add to routing
elif st.session_state.current_page == "new_pathway":
    render_new_pathway()
```

## Known Limitations

### URL Structure

**Current:**
- Single URL for entire application
- No unique URLs for pathways
- Browser back/forward doesn't navigate pathways

**Mitigation:**
- Could implement query parameters if needed
- Could use `st.experimental_set_query_params()`
- Current approach prioritizes simplicity

### Browser Navigation

**Limitation:**
- Browser back button doesn't navigate between pathways
- Only works within Streamlit's session

**Mitigation:**
- "Back to Home" buttons provide clear navigation
- Sidebar always accessible
- Could implement custom history if needed

### SEO Considerations

**Impact:**
- Single-page app has one URL
- Individual pathways not separately indexable
- Less SEO-friendly than multipage

**Mitigation:**
- For public-facing app, could implement server-side routing
- Current approach suitable for internal tools
- Could add meta tags for main page
